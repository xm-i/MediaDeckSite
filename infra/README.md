# インフラ構築・運用手順 (Ubuntu)

このディレクトリには、Ubuntu 本番サーバー上で `MediaDeckSite`（ASP.NET Core `.NET 10` / ポート `5001`）を稼働させるための設定ファイルを格納しています。

## ファイル一覧

- `mediadeck.service` — systemd サービス定義ファイル（`/opt/dotnet10/dotnet` 使用、ポート `5001` 待受）
- `mediadeck.xm-i.net.conf` — Nginx 設定ファイル（静的ファイル `/opt/mediadeck.xm-i.net/wwwroot/` 配信 + `/api/` を `http://127.0.0.1:5001` へ転送、上限 `15M`、Cloudflare Origin SSL 使用）
- `mediadeck-deploy.sudoers` — GitHub Actions（`deploy` ユーザー）がパスワードなしで `mediadeck.service` を再起動するための sudoers 設定
- `init-db.sql` — PostgreSQL データベース・ユーザー・`feedbacks` テーブル初期作成用 SQL スクリプト

---

## サーバー初期セットアップ・切り替え手順

サーバーに SSH ログインし、以下の手順を順に実施してください。

### 1. デプロイ先ディレクトリの権限確認

`deploy` ユーザーが `/opt/mediadeck.xm-i.net` へ `rsync` デプロイおよびファイル削除を行えるよう、ディレクトリを作成して所有権を設定します。

```bash
sudo mkdir -p /opt/mediadeck.xm-i.net
sudo chown -R deploy:deploy /opt/mediadeck.xm-i.net
```

※ 初回のデプロイ完了後、`/opt/mediadeck.xm-i.net/MediaDeckSite.dll` が配置された状態でサービスを起動します（まだ配置されていない場合は先に GitHub Actions の `workflow_dispatch` 等でデプロイを実行してください）。

### 2. systemd サービスの登録・有効化・起動

`infra/mediadeck.service` を `/etc/systemd/system/mediadeck.service` に配置します。

```bash
sudo cp infra/mediadeck.service /etc/systemd/system/mediadeck.service
sudo systemctl daemon-reload
sudo systemctl enable --now mediadeck.service
```

### 3. GitHub Actions 自動再起動用の sudoers 設定

`.github/workflows/deploy.yml` から SSH 経由で `sudo systemctl restart mediadeck.service` を実行できるようにするため、`infra/mediadeck-deploy.sudoers` を `/etc/sudoers.d/mediadeck-deploy` に配置して権限・構文を確認します。

```bash
sudo cp infra/mediadeck-deploy.sudoers /etc/sudoers.d/mediadeck-deploy
sudo chown root:root /etc/sudoers.d/mediadeck-deploy
sudo chmod 440 /etc/sudoers.d/mediadeck-deploy
sudo visudo -cf /etc/sudoers.d/mediadeck-deploy
```

`parsed OK` と表示されれば問題ありません。

### 4. Nginx 設定の更新

既存の `/etc/nginx/sites-available/mediadeck.xm-i.net.conf`（Cloudflare Origin SSL 設定）を `infra/mediadeck.xm-i.net.conf` で上書き更新し、テスト・リロードを行います。
（スクリーンショット添付時の大容量リクエストを受け付けるため、`location /api/` に `client_max_body_size 15M;` を設定しています。）

```bash
sudo cp infra/mediadeck.xm-i.net.conf /etc/nginx/sites-available/mediadeck.xm-i.net.conf
sudo nginx -t
sudo systemctl reload nginx
```

### 5. PostgreSQL データベース・ユーザーの作成と GitHub Secrets 設定

#### PostgreSQL 側の初期作成

`infra/init-db.sql` 内のパスワード（`CHANGE_ME_STRONG_PASSWORD`）を安全な文字列へ書き換えたうえで、`postgres` ユーザーで実行します。

```bash
# 例: パスワードを書き換えた SQL ファイルを実行する場合
sudo -u postgres psql -v ON_ERROR_STOP=1 -f infra/init-db.sql
```

コマンドで直接作成する場合は以下のように実行できます（`<PASSWORD>` は任意のパスワードに置換してください）：

```bash
sudo -u postgres psql <<'SQL'
CREATE USER mediadeck WITH PASSWORD '<PASSWORD>';
CREATE DATABASE mediadeck OWNER mediadeck ENCODING 'UTF8';
\connect mediadeck
ALTER SCHEMA public OWNER TO mediadeck;

SET ROLE mediadeck;

CREATE TABLE IF NOT EXISTS feedbacks (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    category VARCHAR(32) NOT NULL,
    title VARCHAR(500) NOT NULL,
    description TEXT NOT NULL,
    contact VARCHAR(500),
    environment_info TEXT,
    log_content TEXT,
    screenshot_data BYTEA,
    screenshot_mime_type VARCHAR(32),
    screenshot_extension VARCHAR(16),
    submitted_at TIMESTAMPTZ NOT NULL,
    received_at TIMESTAMPTZ NOT NULL,
    client_ip VARCHAR(64)
);

CREATE INDEX IF NOT EXISTS ix_feedbacks_submitted_at ON feedbacks (submitted_at);
CREATE INDEX IF NOT EXISTS ix_feedbacks_category ON feedbacks (category);

RESET ROLE;
SQL
```

※ アプリ起動時のテーブル自動作成は行わないため、初回デプロイ前に `infra/init-db.sql`（または上記の `CREATE TABLE` 文）を手動実行して `feedbacks` テーブルを作成してください。

#### Slack App の設定（通知用 Bot Token の取得）

1. [Slack API](https://api.slack.com/apps) でアプリを作成（From scratch）し、**OAuth & Permissions > Bot Token Scopes** に以下の 2 つの権限を追加します。
   - `chat:write`（通知メッセージの投稿）
   - `files:write`（スクリーンショット画像およびログファイルの添付）
2. ワークスペースへアプリをインストールし、発行された **Bot User OAuth Token**（`xoxb-...`）を控えます。
3. Slack 上で通知先チャンネルを作成（または既存チャンネルを選択）し、チャンネル内で `/invite @<アプリ名>` を実行して Bot を招待します。
4. チャンネル名をクリックして表示される最下部の **チャンネル ID**（`C...`）を控えます。

#### GitHub Secrets の登録

GitHub リポジトリの `Settings > Secrets and variables > Actions` に以下のシークレットを登録してください。デプロイ時に `DB_CONNECTION`・`SLACK_BOT_TOKEN`・`SLACK_CHANNEL_ID` から `publish/appsettings.json` が自動生成されます（いずれかが未設定の場合はワークフローがエラーで停止します）。

| Secret 名 | 用途 | 設定例 |
| --- | --- | --- |
| `DEPLOY_HOST` | デプロイ先サーバーのホスト名 / IP アドレス（既存） | `mediadeck.xm-i.net` |
| `DEPLOY_SSH_KEY` | デプロイ用 SSH 秘密鍵（既存） | `-----BEGIN OPENSSH PRIVATE KEY----- ...` |
| `DB_CONNECTION` | PostgreSQL 接続文字列 | `Host=localhost;Port=5432;Database=mediadeck;Username=mediadeck;Password=<PASSWORD>` |
| `SLACK_BOT_TOKEN` | Slack Bot User OAuth Token | `xoxb-xxxxxxxxxxxx-xxxxxxxxxxxx-xxxxxxxxxxxxxxxxxxxxxxxx` |
| `SLACK_CHANNEL_ID` | 通知先 Slack チャンネル ID | `C0123456789` |

※ 値はそのまま登録でき、手動で JSON 文字列や 1 行 JSON にエスケープする必要はありません（ワークフロー内で `jq` を用いて安全に `publish/appsettings.json` を生成します）。

### 6. 動作確認・ログ確認

```bash
# サービス状態の確認
sudo systemctl status mediadeck.service

# リアルタイムログの確認
sudo journalctl -u mediadeck -f

# バックエンドのヘルスチェック応答確認（ローカル・HTTPS 経由）
curl http://127.0.0.1:5001/api/health
curl https://mediadeck.xm-i.net/api/health
```

`curl` で `{"status":"ok","timestamp":"..."}` が返り、ブラウザから `https://mediadeck.xm-i.net` および `/docs/getting-started` 等にアクセスできれば完了です。
